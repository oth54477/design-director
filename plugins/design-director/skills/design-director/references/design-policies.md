# Design policies

우선순위:

1. 사용자가 이번 요청에서 명시한 요구
2. 저장소에 고정된 디자인 정책과 제약
3. 기존 토큰과 컴포넌트
4. 기존 UI 패턴
5. 외부 스킬의 추천

1과 2가 충돌하면 차이를 말하고 2를 유지한 채 멈춘다. 5 때문에 1~4를 바꾸지 않는다.

## 승인 없이 금지

- UI 라이브러리 교체
- 새 토큰 체계를 기존 체계 옆에 도입
- CSS 프레임워크 교체
- 컴포넌트 API 파괴
- 큰 폴더 구조 변경
- 기능 삭제
- 요청과 관계없는 페이지 수정
- `--persist` 나 `--force` 로 design-system 파일을 덮어쓰기
- Hallmark 를 지명 없이 기존 제품 UI에 적용

더 멋있어 보인다는 이유로 정보 구조와 기능을 빼지 않는다. 기존 화면 개선에서 디자인 시스템 전체를 갈아엎지 않는다. kami 와 huashu 의 문서 모드를 제품 화면 생성에 쓰지 않는다.

## React 와 TypeScript

해당 스택일 때만 적용한다.

- 있는 컴포넌트를 재사용한다.
- 타입을 깨지 않는다. `any` 로 화면을 넘기지 않는다.
- 이미 쓰는 Tailwind 와 토큰 이름만 쓴다. 새 유틸리티 체계를 병행하지 않는다.
- 보이는 이름, 레이블, 포커스, 키보드를 유지한다.
- 의존성을 추가하지 않는다. 애니메이션은 저장소에 이미 있는 CSS 또는 Motion 을 쓴다.
- 컴포넌트 단위로 고친다. 디자인 토큰을 바꾸면 Storybook 과 그 토큰을 쓰는 화면을 범위에 넣는다.
- `prefers-reduced-motion` 을 둔다. 움직임을 줄이고, 상태 변화의 투명도나 색은 남길 수 있다.
- 라이트와 다크가 있으면 둘 다 본다. 하나를 못 보면 보고서에 남긴다.

스택을 확인하지 못했으면 이 절을 적용했다고 쓰지 않는다.
